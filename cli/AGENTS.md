# Go CLI Rules (`cli/`, `twdll`, `twdll.cmd`)

Status: **Stage 1 (including 3-tier E2E verification) Complete; Stage 2 (`extract`, `status` readiness; `search`/`show`/`derive`/`verify` deferred) Active.**
See `./README.md` for commands, env vars, and test workflows, and `../docs/cli_re_pipeline_spec.md` §5–§6 for stage tracking.

## Stage 1 Architecture Invariants (Do Not Regress)

- **Single Native Go Runtime:** Keep dependencies minimal; never introduce Python/`uv` or external runtime requirements into the CLI. Wrapper scripts (`./twdll`, `twdll.cmd`, `twdll.ps1`) check watched `cli/` source timestamps against `.twdll/bin/twdll(.exe)` (skipping when `TWDLL_NO_REBUILD=1`) and compile before launch when stale, avoiding compilation when up to date.
- **Unified `Options` -> `Prompter` -> `Run` Pipeline:** Populate a plain `Options` struct from flags + `twdll.toml`. Invoke an interactive `Prompter` *only* when `stdin` is a TTY (`go-isatty`) and `--no-input` is false. Core `Run*` functions must never read `stdin`; missing inputs in `!TTY` fail fast with a non-zero exit code and actionable `stderr` help. Never build divergent TUI-wizard vs headless-heuristic codepaths.
- **Stream Separation (`Out` vs `Err`) & `!TTY` Purity:** Write primary command data (e.g., `status --json`) solely to injected `Out` (`stdout`) and route all prompts, progress, warnings, and errors to injected `Err` (`stderr`). When `!TTY` or `--color=never`, emit zero ANSI escapes, zero `\r` spinners, and trigger **zero host GUI/OS side effects** (no blocking console reads, no clipboard writes, no `steam://` URL launches).
- **Explicit Workspace Paths & Read-Only `TWDLL_TOOLS_DIR`:** Thread resolved `--root`, `--config`, and `--data-dir` paths explicitly through workspace structs rather than calling `os.Getwd()` inside domain packages. `twdll.toml` stores only user choices and external game/IDA paths — never internal `.twdll/` paths. When `TWDLL_TOOLS_DIR` points to an external shared toolchain directory (`Paths.HasExternalToolsDir()`), treat it as read-only: `EnsureDirs`, `clean`, and `init --clear` must never create, mutate, or delete it.
- **Non-Destructive `state.json`:** Preserve existing target keys on partial updates and write `analyzed_sha256` atomically only after a clean exit code `0`.

## 3-Tier Test Discipline (See `cli/README.md` for Details)

- **Tier 0 — Fast Hermetic Unit Tests (`<5s`, mandatory on every `cli/` edit):** Run `go vet ./...` and `go test ./...` inside `cli/` (fall back to `..\.twdll\tools\go\bin\go.exe` on Windows or `../.twdll/tools/go/bin/go` on POSIX if `go` is not on `PATH`). Isolate via `t.TempDir()` and assert `Out` and `Err` buffers separately.
- **Tier 1 — Quick Real-Decompiler E2E (`~30–45s`, required for lifecycle/decompiler changes):** Run `go test -v -tags=e2e -timeout 5m ./internal/e2e` inside `cli/` whenever modifying `init`, `analyze`, `extract`, `clean`, `status`, `workspace`, decompiler drivers/scripts, or PE/ELF/DWARF inspection. Compiles `testdata/mini_warscape.cpp` and verifies live `twdll.toml` and `.twdll/state.json` remain untouched.
- **Tier 2 — Real-Binary Background Soak (`20–75m`, `6–17 GB` RAM):** Never run `TWDLL_E2E_SOAK=1` synchronously inside an interactive agent turn. Launch detached via `pwsh -NoProfile -File cli/scripts/run-e2e-bg.ps1` only when explicitly validating real game binaries, DWARF import, or memory budgets.

## Stage 2 Extraction, Search & Audit Guardrails

- **Database Naming & Strict Layer Isolation (`.twdll/extracted/`):**
  - `.twdll/extracted/<target>/bronze.sqlite` — Layer 1 (`internal/bronze`): deterministic binary format and DWARF4 parser only (`pe32.format`, `elf64.format`, `data.strings`, `elf64.dwarf4`), extensible via `bronze.Extractor`. Stores `sections`, `relocs`, `imports`, `exports`, `strings` (+ `strings_fts`), `elf_symbols`, and DWARF4 tables (`dwarf_funcs` + `dwarf_funcs_fts`, `dwarf_func_ranges`, `types` + `types_fts`, `type_members`, `enum_values`, `func_vars`, `source_files`, `names`, `inlines`). Zero `.text` disassembly, zero RTTI/vtable/`lua_regs`/thunk heuristics, zero synthetic PE32 `functions`.
  - `.twdll/extracted/<target>/silver_<engine>.sqlite` (`silver_ida.sqlite`, `silver_ghidra.sqlite`) — Layer 2 (`internal/silver`): independent per-engine decompiler exporter with **zero `bronze` dependency** and zero reads of `bronze.sqlite`, extensible via `Enricher` (on disposable staged copies, never `.twdll/db/`), `Selector`, and `Aspect`. Owns `silver_funcs` (+ `silver_funcs_fts`), `silver_func_ranges`, `silver_asm`, `silver_strings` (+ `silver_strings_fts`), and `decomp_funcs` (+ `decomp_fts`, `raw_c`, `line_ea_json`, `vars_json`).
  - **Layer 3 (`derive` / `derived.sqlite`) — DEFERRED:** Heuristic `x86asm` instruction xrefs, RTTI/vtable/`lua_regs` scanners, calling-convention arbitration, and cross-binary symbol matching (`attila_64` <-> `*_32`) are explicitly deferred until `bronze` and `silver` are validated (`derived.sqlite` does not exist yet).
- **Strict Repository Boundary (Zero SQL / Schema Knowledge Outside `internal/extractdb`):**
  - `internal/extractdb` is the **sole owner** of `database/sql`, `modernc.org/sqlite`, SQL queries, `PRAGMA` settings, table/column names, and `meta` cache keys.
  - `internal/cmd` (presentation/CLI orchestration) and domain packages (`internal/bronze`, `internal/silver`, future `derive`/`search`/`show`) must **never** import `database/sql`, embed SQL strings, or hardcode table/column names. They consume only typed domain summaries and repository methods from `extractdb` (e.g., `InspectBronzeStatus`, `InspectSilverStatus`, `BronzeStore.*`, `SilverStore.*`).
  - **Do not bypass repositories via `.DB()` in production code:** Never call `SilverStore.DB()` or `AtomicBuilder.DB()` outside `extractdb` (and tests). If a command or pipeline stage needs a new query, status metric, or write operation, add a typed method + DTO on `extractdb` first.
  - **Verify layer purity on changes:** `internal/extractdb/arch_boundary_test.go` (`TestRepositoryBoundary_NoSQLOrDBBypassInProtectedPackages`) enforces zero `database/sql`/`modernc.org/sqlite` imports and zero `.DB()` calls across production files in `internal/cmd`, `internal/silver`, and `internal/bronze`; keep it passing and extend it to any new Stage 2 packages.
- **Zero Optimism & Continuous Improvement:** Extracted databases are parser, heuristic, and decompiler outputs — never infallible truth. Compiler optimizations (inlining, tail calls, ABI packing), decompiler errors (`in_ECX`, wrong boundaries, variable coalescing), and bugs in our own Go extractors will occur. Always cross-check `bronze.sqlite`, `silver_ida.sqlite`, `silver_ghidra.sqlite`, and raw disassembly. When a bug or blind spot is found during audit or RE, fix the owning extractor in `cli/`, add a unit test, and re-extract.
- **Mandatory Post-Implementation Audit Before Stage 3:** After completing Stage 2 commands (`extract`, plus any deferred `search`/`show`/`derive`/`verify` work), execute a dedicated **Extraction Audit & Hardening Phase** with the user to inspect real Warscape subsystems, compare IDA vs Ghidra vs DWARF vs raw x86 assembly, and fix extractor defects before unlocking Stage 3 (`src/`).
- **Schema & Command Agreement First:** Confirm `.twdll/extracted/` storage layout changes and unimplemented CLI contracts (`search`, `show`, `derive`, `verify`) with the user before implementing them.
- **Native APIs Only:** Read DWARF (Go `debug/dwarf` / `debug/elf`), Ghidra, and IDA APIs directly — never write ad-hoc C++ string lexers or regex syntax parsers.
- **Incremental Vertical Slices:** Build one small extraction/query slice at a time, inspect real extracted records from `.twdll/db/` with the user, then prune or extend.
- **Zero Speculative Bloat:** Do not add cross-binary fuzzy matching hashes, speculative heuristics, or extra tables/indexes before concrete data proves they are needed.
- **Bulk State vs Curated RE Docs:** `twdll extract` writes machine-generated artifacts to gitignored `.twdll/extracted/`; agreed schemas/CLI contracts belong in `docs/cli_re_pipeline_spec.md`, and curated Warscape RE findings (when approved for Git) belong in `docs/research/`.
